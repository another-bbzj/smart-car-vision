# ST7789V2 屏幕不亮排查（NEUQ LCD200 驱动）

更新日期：2026-11-18

适用对象：负责车载 LCD、NEUQ 库移植和硬件接线的同学。

本文针对“换用 ST7789V2 屏幕后完全不亮”的排查。结论先行：NEUQ 的 LCD200 驱动使用 ST7789V 系列初始化序列，ST7789V2 与其寄存器基本兼容，**不亮通常不是 IC 型号不兼容**，而是背光、复位、SPI 时序或模组接线问题。以下步骤均未在本车实机验证，按现象逐项排除。

## 1. 当前驱动事实

| 项目 | 配置 |
|---|---|
| 控制器 | ST7789V / ST7789V2（库内未写型号，由初始化序列判断） |
| 分辨率 | 240×320，横屏后 320×240 |
| 接口 | SPI3，4 线，8 位命令/数据 |
| 引脚 | SCK=PB3，MOSI=PB5，CS=PB4，DC=PD5，RST=PE2，BL=PD3 |
| SPI 模式 | 主机、Mode 0、MSB first、单线只发、约 21 MHz |
| 颜色 | RGB565，每像素 2 字节，按高字节、低字节发送 |
| 传输方式 | `HAL_SPI_Transmit` 阻塞发送，无 DMA、无帧缓冲 |
| 背光 | PD3 高电平点亮 |

代码位置：

- 引脚和尺寸：[NEUQ_LCD200.h](../Library/NEUQ_lib/NEUQ_lib_Device/NEUQ_LCD200.h#L39-L49)
- 初始化序列：[NEUQ_LCD200.c](../Library/NEUQ_lib/NEUQ_lib_Device/NEUQ_LCD200.c#L119-L234)
- SPI 配置：[NEUQ_Hard_SPI.c](../Library/NEUQ_lib/NEUQ_lib_Driver/NEUQ_Hard_SPI.c#L104-L126)
- 本工程入口：[Car_Hardware.c](../CODE/Car_Hardware.c#L1017)、[My_Lcd.c](../CODE/My_Lcd.c#L29-L33)

初始化命令序列：

```text

0x3A 0x05              COLMOD，16 位 RGB565
0xB2 0C 0C 00 33 33    PORCTRL
0xB7 0x35              GATECTRL
0xBB 0x19              VCOM
0xC0 0x2C              LCMCTRL
0xC2 0x01              VDV/VRH
0xC3 0x12              VRHS
0xC4 0x20              VDVS
0xC6 0x0F              60 Hz
0xD0 A4 A1             PWCTRL1
0xE0 / 0xE1            正/负伽马
0x21                   INVON，常黑面板反显

```

## 2. 先按现象分层

| 现象 | 含义 | 首先检查 |
|---|---|---|
| 背光完全不亮（全黑） | 背光没供电，或初始化没走到开背光 | BL 电平、模组供电、初始化是否卡死 |
| 背光亮但全黑 | 通信、复位或地址窗口有问题 | SPI、DC/CS、RST、MADCTL/COLMOD |
| 背光亮但整屏白或花屏 | 通信已通，参数不对 | `0x21` 反显、颜色格式、方向 |

**第一步永远是量 PD3（BL）**。`My_Lcd_init()` 执行完后它应为高电平（约 3.3 V）。如果一直为低，说明 [NEUQ_LCD200.c:233](../Library/NEUQ_lib/NEUQ_lib_Device/NEUQ_LCD200.c#L233) 没有被执行到。

## 3. 背光完全不亮

### 3.1 背光极性和驱动能力

- 多数模组 BL 高电平点亮，但存在低电平点亮的模组。先查模组资料或丝印。
- 部分模组的 BL 直接接 LED 串，没有三极管。2.0 寸 IPS 背光通常需要几十 mA，STM32 的 GPIO 无法直接驱动。
- 快速验证：把模组 BL 直接接 3.3 V（若为低有效则接 GND），不要经过 PD3。
  - 亮了：GPIO 驱动能力或极性有问题，加三极管或改配置。
  - 仍不亮：模组背光供电或模组本身有问题。

### 3.2 供电和地

- 量模组 VCC 是否稳定 3.3 V，背光点亮的瞬间是否被拉低。
- 确认双方 GND 共地。
- 确认模组工作电压与板子输出一致（3.3 V 模组不要接 5 V）。

## 4. 背光亮但全黑

### 4.1 初始化是否真的跑完

两个容易卡住的位置：

1. **`printf` 阻塞。** `NEUQ_LCD200_init` 在命令之间调用了 `printf`。如果调试串口没有初始化，`printf` 会阻塞，此时 `0x36` 已发出、参数还没发出，后续初始化全部不执行，背光也不会亮。
   - 本工程已经在 [Car_Hardware.c:946](../CODE/Car_Hardware.c#L946) 调用 `NEUQ_Debug_set_output_enabled(0)`，`fputc` 直接返回，不会阻塞。
   - 在其他工程直接复用该驱动时，必须先初始化调试串口，或者关闭 printf 输出。
2. **`NEUQ_LCD200_Clear()` 很慢。** 它按 320×240 逐像素阻塞发送，共 76800 次 `HAL_SPI_Transmit`。如果 SPI 配置异常，可能停在这里。用调试器暂停，看 PC 是否停在 `NEUQ_LCD200_init` 或 `NEUQ_LCD200_Clear`。

本工程还有一个可观察现象：`My_Lcd_init()` 在蓝牙串口初始化之前执行（[Car_Hardware.c:1017](../CODE/Car_Hardware.c#L1017)）。如果屏幕初始化卡死，后续 MPU6050 和蓝牙 UART 都不会初始化，表现为“整车没反应、蓝牙也连不上”。这可以作为初始化卡死的旁证。

### 4.2 SPI 时钟过高

[NEUQ_Hard_SPI.c:111-112](../Library/NEUQ_lib/NEUQ_lib_Driver/NEUQ_Hard_SPI.c#L111-L112) 中 SPI3 使用分频 2，约 21 MHz。部分 ST7789V2 模组的写时序上限低于此值。

临时把 LCD 的 SPI3 分频改为 4（约 10.5 MHz），重新编译测试。该修改只影响 SPI3（LCD），不影响 SPI1（板载 Flash）。

```c
/* NEUQ_Hard_SPI.c 中 SPI3 的分频设置 */
Handle_use->Init.BaudRatePrescaler = SPI_BAUDRATEPRESCALER_4;
```

如果 10.5 MHz 能亮，再视需要尝试 21 MHz；不要只改一次就下结论。

### 4.3 缺少软件复位

新模组的 RST 可能没有接到 PE2，或者上电复位不充分。在 `NEUQ_LCD200_init` 发送 `0x36` 之前加入：

```c
NEUQ_LCD200_WriteCommand(0x01);   /* SWRESET */
HAL_Delay(150);
```

之后仍按原来的 `0x11` + 120 ms + `0x29` 执行。该命令对 ST7789V 和 V2 都安全。

### 4.4 判断是否存在有效通信

临时注释掉 [NEUQ_LCD200.c:207](../Library/NEUQ_lib/NEUQ_lib_Device/NEUQ_LCD200.c#L207) 的 `0x21`（INVON），重新烧录：

- 屏幕变成全白：SPI 和初始化已经通了，问题在反显或颜色参数，恢复 `0x21` 或按模组类型调整。
- 仍然全黑：命令没有进入控制器，转到第 5 节检查硬件。

也可以在原初始化结束后直接做一次全屏填色，绕开菜单和字体：

```c
NEUQ_LCD200_SetBackColor(LCD_RED);
NEUQ_LCD200_Clear();
```

红色能显示，说明驱动链路完整；不能显示，问题在初始化或硬件。

### 4.5 用示波器或逻辑分析仪核对

依次检查以下信号：

| 信号 | 预期 |
|---|---|
| PB3 SCK | 初始化时有约 21 MHz 的突发时钟 |
| PB5 MOSI | 有对应数据 |
| PB4 CS | 每个字节或每次批量写入时拉低 |
| PD5 DC | 命令期间低，数据期间高 |
| PE2 RST | 初始化时低脉冲后保持高 |
| PD3 BL | 初始化结束后保持高 |

如果 SCK/CS/DC 完全没有动作，说明代码没有进入 LCD 初始化，先回到 4.1。如果信号都有但屏幕无反应，检查模组接口模式和接线。

## 5. 模组接口和接线

按可能性排序：

1. **排线定义不一致。** 新模组的 BL/CS/DC/RST/SDA/SCL/VCC/GND 顺序、正反面、引脚数必须与原屏一致。错一个脚就不亮，这是换屏最常见的原因。
2. **接口模式不是 4 线 SPI。** 如果模组是 3 线 9 位 SPI（没有 DC 脚），或者背面 IM0/IM1/IM2 焊盘没有选择 4 线模式，NEUQ 这套 8 位命令/数据驱动无法使用。需要确认模组资料，必要时改发送格式或改焊盘。
3. **模组型号与分辨率不匹配。** 1.69 寸 240×280、1.9 寸 170×320 等 ST7789V2 模组需要不同的行列偏移，不能直接套 240×320 的初始化。
4. **背光极性和驱动能力。** 见第 3 节。
5. **供电。** 见 3.2 节。

## 6. 建议的排查顺序

1. 量 PD3 是否为高，判断初始化是否走到开背光。
2. 把 BL 直接接 3.3 V（或 GND），判断背光本身和驱动能力。
3. 把 SPI3 分频改为 4，加 `0x01 + 150 ms` 软复位。
4. 注释 `0x21`，并做全屏红色自检，判断通信是否成功。
5. 对照模组丝印和引脚定义，确认 4 线 SPI、引脚顺序和分辨率。
6. 以上都正常仍不亮，用示波器核对 SCK/CS/DC/RST/BL 波形。

## 7. 需要向硬件/屏幕提供方确认的信息

- 模组完整型号和丝印。
- 引脚定义及引脚数，特别是有没有 DC 脚。
- 背面 IM0/IM1/IM2 的选择状态。
- BL 的极性、额定电流和是否板载三极管。
- 分辨率（240×320 / 240×280 / 170×320）和是否需要行列偏移。
- 工作电压和逻辑电平。

如果为了排查临时修改了驱动，请在提交或交接时注明：

- 改了哪个文件、哪一行；
- 原始值和测试值；
- 测试结果（亮/不亮、全白/全红）；

排查完成后，把临时的降频、软复位、注释反显等改动恢复或按最终模组固化，避免影响已经验证过的屏幕。
