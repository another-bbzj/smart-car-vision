# 内环自动调参（适配 PRC / FOPDT）

适用：NEUQ_STM32F407VET6 双轮差速底盘，网页调试台的内环速度环自动调参。

相关代码：[Car_Config.h](../CODE/Car_Config.h)、[Car_Core.c](../CODE/Car_Core.c)、[car_console.html](../Tools/car_console.html)。
配套文档：[蓝牙调试协议](Bluetooth_Car.md)、[转速—PID 调参指引](Speed_PID_Tuning_Guide.md)、[速度控制升级](Speed_Control_Upgrade.md)。

## 1. 为什么不能直接运行 mazj/PythonPID_Tuner

`mazj/PythonPID_Tuner` 是离线 FOPDT 调参器：读 100 ms 的 `CV`/`PV` CSV，对开环阶跃响应拟合
`G(s) = K·e^(-θs)/(τs+1)`，再用 CHR/IMC/AIMC 公式计算增益。它有两个硬编码的**时间尺度**：

- `step2.py` 用 2 s / 1 s / 5 s 窗口寻找死区和时间常数；
- `step3.py` 每 10 行取一个点，即把 100 ms 数据降采样到 1 s。

用仓库自带的 `PRC.csv` 复核，粗模型约为 **K=2.14、τ=219 s、θ=27.9 s**，说明它面向分钟级慢过程。
轮速内环的 τ 通常只有 **0.1–0.5 s**：2 s 窗口内响应早已到终值，`AvgAti≈终值`，增益会被估成接近 0
（同尺度试算得到 K=0.0075，真值 0.05；τ=-1），`step3` 的 1 s 降采样更会直接丢掉瞬态。

因此本项目**没有直接移植原工具**，而是在网页里实现了一个时间尺度适配版：

1. 用 100 ms 遥测采集开环 PWM→rpm 的阶跃响应；
2. 用短窗口/连续时间网格搜索拟合 FOPDT；
3. 用同一组 CHR/IMC/AIMC 公式，但把增益换算到固件的 PWM/rpm 和 5 ms 离散 Ki/Kd 约定；
4. 自动加安全系数和整车上限，Kd 默认不启用。

外环位置环不适配：它的被控对象是 rpm→位置（积分型），FOPDT 的有限稳态增益模型不适用；当前固件也没有
外环增益/位置目标协议，因此网页把外环分区保留但置灰。

## 2. 固件新增：命令 6 OPENLOOP

```
C3 3C | 06 | 03 | wheel u8 | pwm int16 大端 | CRC8
```

- `wheel`：0 左轮、1 右轮；一次只测试一轮。
- `pwm`：带符号 PWM 数值，范围 `[-CAR_OPENLOOP_PWM_LIMIT, +CAR_OPENLOOP_PWM_LIMIT]`，
  默认 3000（满量程 10000 的 30%）。
- 只在 `RUN` 状态接受；首次进入还要求双轮目标为零且实测转速低于 10 rpm，
  防止行驶中直接切换；周期刷新不受此限制。
- `STOP`、故障、轮速命令和超时都会撤去开环输出。
- 上位机必须每 `CAR_OPENLOOP_TIMEOUT_MS`（默认 500 ms）内刷新，否则该轮自动回零。
- 开环期间仍保留超速、堵转和方向保护；参考转速按 0 处理，堵转/方向条件改用开环标志。
- 开环命令会清空规划器和另一轮的开环状态，并刷新通信看门狗。

安全前提：**车轮必须架空**。网页要求同时勾选“安全确认”和“车轮已架空”，并且开始后按空格/停止、
窗口失焦、切后台或断链都会中止并发送 STOP。

## 3. 网页自动调参流程

1. 连接串口，收到停止回传，勾选安全确认和“车轮已架空”。
2. 在“PID 调参 → 自动调参”选择内环、轮、阶跃 PWM（200–3000）、持续时间（2–6 s）和方法。
3. 点击“开始内环自动调参”。按钮变为橙色并显示“调参中…”，流程自动执行：
   - ARM，等待运行状态；
   - 开环 0 保持 1 s，采集基线；
   - 施加阶跃 PWM，持续设定时间；
   - 开环 0 收尾 0.5 s；
   - 发送 STOP，等待停止回传；
   - 拟合 FOPDT，计算增益并填入所选轮的输入框，然后自动写入一次。
4. 核对模型、实际增益和“实际内环 PID”回传；如果手动改了滑块，再点“应用并写入所选轮”重写。
5. 需要掉电保留时，在板端 PID 菜单执行 `Save parameters`。

网页的“应用并写入”只写内环；外环当前不能写。

## 4. 拟合与增益换算

模型：`PV(t) = PV0 + K·ΔCV·(1 - e^(-(t-θ)/τ))`，`t ≥ θ`。

- `ΔCV` 是实际 PWM 阶跃（遥测通道 6/7 的百分比 ×100）；
- `K` 单位是 **rpm/PWM**；
- `θ` 和 `τ` 单位是秒；
- 网页对 `τ`、`θ` 做二维网格搜索，`K` 在每个网格点用最小二乘解析求出；
- 要求 `R² ≥ 0.5`，`R² < 0.85` 会给出警告；轮速没有明显上升（<10 rpm）、
  起始转速超过 20 rpm 或拟合失败都会中止。

固件内环的 Ki/Kd 沿用 5 ms 离散约定，换算关系为：

```text
Kp_fw = 0.35·τ/(K·θ)                 (CHR，其他方法见网页)
Ki_fw = Kp_fw/(200·Ti)               Ti = 1.2τ（CHR）
Kd_fw = (10/3)·Kp_fw·Td              Td = 0.5θ（CHR）；默认不启用
```

其中 `Kp_fw` 为 PWM/rpm，`Ki_fw` 为每个 5 ms 控制周期的 PWM/rpm，`Kd_fw` 为 5 ms 离散微分增益。
网页对所有方法再乘 0.8 安全系数，并限制 `Kp ≤ 14`、`Ki ≤ 1.5`；如果 Kp 被上限截断，Ki 会按
同一比例缩放以保持 `Ti=Kp/Ki` 不变。Kd 默认写 0，结果里只显示原始建议值。

## 5. 结果可信度与验证

自动调参给出的是**起点**，不是实车性能保证。落地前至少做：

1. 左右轮分别架空调参，写同一组增益后再落地；
2. 100 rpm 直行 1–2 m，稳态误差 ≤ ±2–3 rpm，左右差 ≤ ±2 rpm；
3. PWM 纹波 ≤ 50–100（0.5–1% 占空比），无持续啸叫；
4. 阶跃超调 < 5–10%，无 0.2–0.5 s 周期低频摆动；
5. 若 R² 低、模型 τ/θ 与预期差很多，先检查编码器计数、方向符号、轮子是否真的架空、阶跃是否足够大。

测速链路本身有约 35 ms 延迟（40 ms 窗口 + 15 ms 低通），这部分会被拟合进 θ/τ；不要因为自动结果比手调
更激进就直接落地，先用小目标转速验证。
